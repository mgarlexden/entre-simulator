## 0. 먼저 할 일 (충돌 방지)

1. 작업 전에 새 브랜치를 만든다. `main`(또는 현재 기본 브랜치)에서 바로 수정하지 않는다.
   ```
   git status            # 수정 중인 파일이 있으면 먼저 사용자에게 알린다
   git switch -c feat/location-ux
   ```
2. 이 폴더(`docs/design-handoff/`)도 그 브랜치에 같이 커밋한다.
3. push·PR은 사용자가 요청할 때만 한다.

## 2. 구 단위 화면 (안 1) — 바꿀 점

위에서 아래로 이 순서, 각 층은 역할 하나만 가진다.

1. **제목 = 동네 선택창**: `마포구 [구 전체 ▾]`. 기존 '목록에서 동네 고르기' 드롭다운을 제목 옆 알약 모양 select로 옮긴다. 동을 고르면 `○○구 전체로 돌아가기` 버튼을 보인다. 지도에서 동을 눌러도 같은 상태(선택된 동)가 바뀌어야 한다 — 선택 상태는 하나.
2. **왼쪽 큰 칸**
   - `○○구 한눈에 보기` 요약 카드. 제목을 "이런 점이 좋아요!"에서 바꾼다. `주의할 점 / 눈여겨볼 점` 두 묶음.
   - 각 줄 = **태그 + 문장 한 줄**. 태그를 오른쪽 따로 놓지 않고 줄 맨 앞에 둔다. 태그 없는 문장, 문장 없는 태그가 없게 1:1.
   - 태그를 누르면 아래 지표 카드 중 짝이 되는 카드가 선택된다.
   - 순위 표기는 기준을 풀어 쓴다: `(25번째)` → `25개 구 중 가장 많이 줄었어요`.
3. **지표 카드 4개 = 탭** (매출 · 경쟁 · 비용 · 생존). 카드마다 대표 숫자 1개 + 오른쪽 위에 요약의 태그를 그대로 붙인다. 누른 카드의 근거만 아래 패널에 나온다.
   | 요약 태그 | 카드 | 아래 근거 (위에 없는 것만) |
   |---|---|---|
   | 성장 둔화 | 매출: 점포당 월매출 + 전년 대비 | 하루 결제 건수, 매출 지수 |
   | 경쟁 치열 | 경쟁: 고깃집 수(순위) | 한식음식점 수 + 구성 |
   | 월세 높음 | 비용: 평당 월세 | 월세 범위, '내 매물 월세' 입력칸 |
   | 폐업 많음 | 생존: 1년 폐업률 | 가게 수 흐름(개업률-폐업률) |
   - 기존 '수요와 성장' 카드는 없애고 '생존' 카드로 바꾼다. 기존 '구 매출 성장' 상세 행도 없앤다 (-4.1%가 5번 반복되던 문제).
   - 근거 행마다 기준 배지를 단다: `고깃집 · 구 전체`, `한식음식점 · 구 안 상권` 등. 업종(고깃집/한식)과 범위(구/동/상권)가 섞이지 않게.
4. **오른쪽 옆 칸 '이런 동네는 어때요?'** (추천 동네). 데스크톱에서는 오른쪽 sticky 칸, 좁은 화면에서는 아래로. 흰 바탕 + 진한 파란 테두리(#3639B8 2px) + 그림자 + '추천 동네' 배지 + 카드마다 `›`. 카드를 누르면 1번의 선택창 값이 바뀌고 카드에 '보는 중' 표시.
   - 그룹 이름 수정: '작아도 크는 동네' → '규모는 작아도 성장하는 동네'.
   - '매출이 크고 꺾이지 않은 동네' 그룹은 **성장률 0% 이상만** 넣는다 (예: 한남동 -0.9%가 들어가 있던 버그).

## 3. 동 단위 화면 — 바꿀 점

구 단위 구조(제목 선택창 → 요약 → 지표 탭 → 옆 칸 추천)를 그대로 쓰고, 아래를 추가·변경한다.

1. **상권 키워드 강조 띠** (요약 카드 위, 진한 남색 #26288A 배경)
   - 큰 글씨 키워드(예: `뜨는 생활 상권형`) + 보조 배지(예: `4050 단골`) + 한 줄 설명.
   - 키워드를 이루는 단어마다 근거 카드 1개: 뜨는=한식 매출 증감, 생활=주민/직장인 수, 고르게=주말·저녁 매출 비중, 4050 단골=40·50대 매출 비중.
   - 키워드는 이미 프로그램에 있는 규칙(업종별, 매출이 줄어드는 상권용 키워드 포함)을 그대로 쓴다. 새 규칙을 만들지 않는다.
2. **'그래서 ○○동 안에서는 어디가 좋을까요?'** (키워드 띠 바로 아래, 새 섹션) — 아래 4장 참고.
3. **경쟁 탭 근거 구체화** (업종이 고깃집일 때)
   - 직접 경쟁 요약 3칸: 고깃집 수 / 1㎢당 고깃집(서울 '약함' 기준선과 비교) / 주민+직장인 몇 명당 1곳.
   - 고깃집 상호 목록(칩).
   - 한식음식점 중 고깃집 비중 막대 + **나머지 한식 소분류 구성 막대**(백반·한정식, 국수, 국·탕·찌개, 곱창, 닭·오리 구이 …). 서울 평균보다 비중이 높은 구이 계열은 강조색. "고기 구이로 넓게 보면 N곳" 문장.
   - 주변 음식점 구성(서울시 상권분석 9종).
4. **카페 업종일 때 경쟁 탭** (`mockups/CafeComp.dc.html`)
   - 카페 수 / 1㎢당 카페(서울 동네 분위) / 최근 1년 개업·폐업.
   - 구성 막대: 저가 프랜차이즈 · 그 외 프랜차이즈 · 개인 커피전문점 · 개인 디저트·음료 · 무인.
   - 서울 비교 행: 프랜차이즈 비중, 저가 비중, 1년 폐업률, 카페 1곳당 주민, 1층 카페 비중.
   - **브랜드 칩**: 저가 커피 / 그 외 프랜차이즈로 나눠 브랜드명·지점명. 같은 지점 중복 등록은 한 번만 센다.

## 4. 동 안 상권 추천 — 데이터와 규칙

### 데이터 (서울시 상권분석서비스, 사용자 다운로드 폴더에 원본 있음)
- `서울시 상권분석서비스(영역-상권).csv` — 상권 코드 → 자치구·행정동, 유형(골목/발달/전통시장/관광특구). **cp949 인코딩**.
- `서울시 상권분석서비스(추정매출-상권).csv` — 분기별 업종별 매출. utf-8.
- `서울시 상권분석서비스(점포-상권).csv` — 분기별 업종별 점포·프랜차이즈·개업·폐업 수. utf-8.
- 업종 코드: 한식음식점 `CS100001`, 커피-음료 `CS100010`.
- 원본은 저장소에 넣지 않는다(용량). 다른 fetch 파이프라인처럼 `data/raw/`에 두거나 API로 받는다.

### 상권별 지표 (`scripts/trdar.py` 참고)
- 점포당 월매출(만원) = 최근 분기 매출 ÷ 3 ÷ 점포 수 ÷ 1만
- 1년 매출 증감 = 최근 분기 / 1년 전 같은 분기 − 1
- 최근 4분기 개업 수·폐업 수 합
- 주말 비중, 시간대 비중, 20·30대 / 40·50대 매출 비중
- 비교 기준: 서울 상권(해당 업종 점포 5곳 이상)의 점포당 월매출 25·50·75분위

### 라벨 규칙 (제안 — 사용자와 확정 필요)
- 대상: 선택한 동에 속한 상권 중 해당 업종 점포 5곳 이상이고 매출 자료가 있는 곳.
- `성장`: 1년 매출 증감이 가장 높고 0% 초과.
- `안정`: 점포당 월매출이 동 안에서 가장 높고, 최근 4분기 폐업 수 ≤ 점포 수의 10%.
- `조심`: 1년 매출 −15% 이하 이거나 폐업 수 > 개업 수 × 1.5.
- 한 상권에 라벨이 겹치면 성장 > 안정 > 조심 순. 카드마다 '주의' 한 줄(데이터에서 나온 것만).
- 문장은 숫자로만 말한다. 현장 조사·추측(예: "빈 점포가 잘 안 나와요")은 쓰지 않는다.

### 알려진 한계 (화면 각주에 반영)
- 서울시 데이터는 상권마다 중심이 속한 **행정동 하나**에만 붙는다. 예: 월드컵경기장역 상권은 성산2동이라 서교동을 골라도 안 나온다. 맞닿은 동의 상권을 '근처 상권'으로 같이 보여줄지는 다음 단계.
- 상권별 매출·점포는 한식음식점 전체 기준이다. 상권별 **고깃집 수**는 아직 없다(상가정보 좌표를 상권 경계에 겹치면 셀 수 있음).
- 한식 매출 증감은 동 전체 한식 매출이라 점포 수 변화가 섞여 있다. '점포당'으로 표기하지 않는다.
